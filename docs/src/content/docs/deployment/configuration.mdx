FxEmbed is configured through environment variables (`.env`), Wrangler settings (`wrangler.toml`), and an optional branding file (`branding.json`).

## Environment Variables

Copy `.env.example` to `.env` and configure:

### Domain Lists

These comma-separated lists define which domains route to which realm:

| Variable                      | Description             | Example                                |
| ----------------------------- | ----------------------- | -------------------------------------- |
| `STANDARD_DOMAIN_LIST`        | X/Twitter embed domains | `fxtwitter.com,fixupx.com,twittpr.com` |
| `STANDARD_BSKY_DOMAIN_LIST`   | Bluesky embed domains   | `fxbsky.app`                           |
| `STANDARD_TIKTOK_DOMAIN_LIST` | TikTok embed domains    | `fixtok.example.com`                   |

### Subdomain Feature Domains

| Variable               | Description                           | Example                            |
| ---------------------- | ------------------------------------- | ---------------------------------- |
| `DIRECT_MEDIA_DOMAINS` | `d.`/`dl.` direct media subdomains    | `d.fxtwitter.com,dl.fxtwitter.com` |
| `TEXT_ONLY_DOMAINS`    | `t.` text-only subdomains             | `t.fxtwitter.com`                  |
| `INSTANT_VIEW_DOMAINS` | `i.` Telegram Instant View subdomains | `i.fxtwitter.com`                  |
| `GALLERY_DOMAINS`      | `g.` gallery subdomains               | `g.fxtwitter.com`                  |
| `FORCE_MOSAIC_DOMAINS` | `m.` mosaic subdomains                | `m.fxtwitter.com`                  |
| `OLD_EMBED_DOMAINS`    | `o.` legacy embed subdomains          | `o.fxtwitter.com`                  |

### API Domains

| Variable                | Description           | Example             |
| ----------------------- | --------------------- | ------------------- |
| `API_HOST_LIST`         | FxTwitter API host(s) | `api.fxtwitter.com` |
| `BLUESKY_API_HOST_LIST` | FxBluesky API host(s) | `api.fxbsky.app`    |

| Variable                           | Description                                 |

### LLM Translation

When Polyglot is not configured (or fails), translation falls back to an LLM. On Cloudflare this uses the Workers AI `AI` binding. You can instead point it at any OpenAI-compatible chat completions endpoint, which also enables translation for self-hosted deployments without Workers AI, such as the Docker image. When set, the endpoint is tried before the Workers AI binding.

| Variable                     | Description                                                          |
| ---------------------------- | -------------------------------------------------------------------- |
| `LLM_TRANSLATION_BASE_URL`   | Base URL ending in the API version, e.g. `https://api.openai.com/v1` |
| `LLM_TRANSLATION_API_KEY`    | Sent as `Authorization: Bearer <key>` (optional for local servers)   |
| `LLM_TRANSLATION_MODEL`      | Model name passed to the endpoint                                    |
| `LLM_TRANSLATION_EXTRA_BODY` | Optional JSON object merged into the request body                    |

Both `LLM_TRANSLATION_BASE_URL` and `LLM_TRANSLATION_MODEL` must be set to enable it. For example, a [llama.cpp](https://github.com/ggml-org/llama.cpp) server running in the same network namespace as FxEmbed:

```bash
LLM_TRANSLATION_BASE_URL = "http://localhost:8080/v1"
LLM_TRANSLATION_MODEL = "local"
```

Reasoning models are slow to translate while thinking is on. Most providers accept a request field to turn it off, which `LLM_TRANSLATION_EXTRA_BODY` can send, e.g. `{"chat_template_kwargs":{"enable_thinking":false}}` for llama.cpp and vLLM. Literal `<think>` markers copied from the source post are protected before translation and restored afterward. Generated `<think>…</think>` reasoning blocks are removed, including inline and repeated blocks, while preserving surrounding translation text. Responses that lose or duplicate protected source markers are rejected. A closing marker without an opening marker is preserved because it may be literal post content; use a server-side reasoning parser or disable thinking for servers that omit the opening marker. Unfinished blocks and responses marked as truncated are rejected so the existing fallback can run; unmarked text is preserved.

The endpoint attempt has a 10-second deadline covering both the request and response body. Redirects are not followed; a 3xx response uses the existing fallback. When an API key is configured, the endpoint must use HTTPS; keyless HTTP remains available for local servers.

#### Docker runtime configuration

The Docker image runs Wrangler locally. Set the four translation values in a private `translation.dev.vars` file and mount it read-only at `/app/.dev.vars`, next to `wrangler.toml`. These runtime bindings override the build-time defaults; setting only Docker process environment variables does not configure the Worker. Keep the file out of source control and readable only by its owner and the container user.

For Docker Compose, add a local override:

```yaml
services:
  fxembed:
    volumes:
      - ./translation.dev.vars:/app/.dev.vars:ro
```

Use `http://host.docker.internal:8080/v1` for a keyless llama.cpp server on the Docker Desktop host. Inside the container, `localhost` refers to FxEmbed itself. On Linux, configure a host-gateway mapping for `host.docker.internal`, or use a reachable service name on the same Docker network. Use HTTPS for endpoints that require a key.

See [Wrangler local environment bindings](https://developers.cloudflare.com/workers/local-development/environment-variables/) for `.dev.vars` loading and precedence.

## Wrangler Configuration

The `wrangler.toml` file configures the Cloudflare Worker:

```toml
name = "fxembed"
account_id = "YOUR_ACCOUNT_ID"
main = "./dist/worker.js"
compatibility_date = "2026-04-11"
send_metrics = false

analytics_engine_datasets = [
  { binding = "AnalyticsEngine" }
]

[build]
command = "npm run build"
```

### Key Settings

- **`name`**: Worker name (appears in `*.workers.dev` URL)
- **`account_id`**: Your [Cloudflare Account ID](https://developers.cloudflare.com/fundamentals/get-started/basic-tasks/find-account-and-zone-ids/)
- **`compatibility_date`**: Cloudflare Workers API compatibility date
- **`analytics_engine_datasets`**: Remove this block if you don't use Cloudflare Analytics Engine

### Secrets

Some values should be set as Wrangler secrets rather than in `.env` or `wrangler.toml`:

```bash
wrangler secret put CREDENTIAL_KEY
wrangler secret put EXCEPTION_DISCORD_WEBHOOK
```

- **`CREDENTIAL_KEY`**: Encryption key for credential storage
- **`EXCEPTION_DISCORD_WEBHOOK`**: Discord webhook URL for exception notifications

## Branding

Copy `branding.example.json` to `branding.json` to customize the appearance and behavior of each domain zone.

Each zone in the `zones` array defines:

```json
{
  "name": "FxTwitter",
  "default": true,
  "domains": ["fxtwitter.com", "twittpr.com"],
  "provider": "twitter",
  "favicon": "https://example.com/favicon.ico",
  "redirect": "https://github.com/FxEmbed/FxEmbed",
  "color": "#6363ff",
  "activityIcons": {
    "default": "https://example.com/icon32.png",
    "svg": "https://example.com/icon.svg",
    "16": "https://example.com/icon16.png",
    "32": "https://example.com/icon32.png"
  }
}
```

| Field           | Description                                                                           |
| --------------- | ------------------------------------------------------------------------------------- |
| `name`          | Display name for this zone                                                            |
| `default`       | Whether this is the default zone (only one should be `true`)                          |
| `domains`       | Domains this zone applies to                                                          |
| `provider`      | Content provider (`twitter`, `bluesky`, `tiktok`)                                     |
| `favicon`       | URL to the favicon served for this zone                                               |
| `redirect`      | Where bare domain visits redirect to                                                  |
| `color`         | Theme color for embeds (hex)                                                          |
| `activityIcons` | Icon URLs at various sizes; `activityIcons` can also be an array for random selection |
